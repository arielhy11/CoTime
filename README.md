# CoTime 📵💣

Phones down, eyes up. A party game for meetups: everyone puts their phone
face down on the table, and CoTime catches whoever picks theirs up first.
Their profile picture gets cracked, band-aided, set on fire, or bombed.

Same stack as CoMission: **Expo 54 + expo-router · Firebase (Auth + Firestore)
· Zustand · NativeWind · i18next (English + Hebrew/RTL) · Reanimated · Jest.**

## Game modes

| Mode | Rule |
| --- | --- |
| 💣 **Sudden Death** | First to touch their phone loses, instantly. Optional timer: survive it and everyone wins. |
| 💥 **Three Strikes** | Each pickup costs a heart (1–5). Out of hearts = blown up. Last one standing wins. |
| 🧘 **Zen Master** | Fixed time. Fewest pickups wins; ties go to least time on the phone. Most pickups gets bombed. |
| ⏳ **Screen Time Budget** | Everyone gets the same phone-time budget (1–10 min). The clock runs only while it's in your hand. Run out = boom. |

Extras in every mode:

- **Stakes**: the loser owes something ("Pays the bill", "Buys the next round", or anything you type).
- **Face damage**: pristine → cracked → band-aid → on fire → bombed. The cracks are seeded by player id, so every phone draws the same cracks on the same face.
- **Your phone snitches**: when a friend picks theirs up, every face-down phone at the table plays a siren and buzzes. An elimination plays an explosion. Sounds play even on silent mode, and you can turn them off in your profile.
- **Results**: crown for the winner, a replayable bomb on the loser ("tap to bomb again"), standings, and awards: Monk Mode, Quickest Draw, Phone Zombie, Longest Doomscroll, Can't Stop. The host can start a one-tap rematch.

## How a pickup is detected

`src/game/pickupDetector.ts` is a pure state machine fed by the accelerometer:

- **Placed**: the phone is flat (either side up) and still for 1.2 s. That resting position becomes the baseline.
- **Pickup**: any of these counts:
  - tilting more than 35° away from the baseline for 300 ms
  - a straight-up lift (acceleration changes by more than 0.35 g)
  - touching the screen
  - leaving the app (including pressing the power button)
  - the Android back button
  - not placing the phone within 20 s of the start. Other phones at the table enforce this too, so you can't dodge it by closing the app.
- **Put back**: flat and still again.

The screen stays on during a game (keep-awake). Players should put the phone face down and not lock it.
On web or a simulator (no sensors), "My phone is down" / "I put it back" buttons stand in.

## Setup

1. **Firebase project.** Create one at <https://console.firebase.google.com>, then:
   - Go to **Authentication → Sign-in method** and enable **Anonymous**. Players never sign up; they just pick a name and take a selfie.
   - Create a **Firestore Database**.
   - Add a **Web app** and copy its config values.

   No Cloud Storage or Blaze plan is needed: avatars are stored as small JPEGs (about 30 KB) on the user document.

2. **Env vars.**
   ```bash
   cp .env.example .env   # paste the Firebase web config values
   ```

3. **Install and align native module versions.**
   ```bash
   npm install
   npx expo install --fix
   ```

4. **Deploy the security rules and index.**
   ```bash
   npx firebase-tools login
   npx firebase-tools use --add      # pick your project
   npm run deploy:rules
   ```

5. **Run.**
   ```bash
   npm start            # scan the QR code with Expo Go on two or more phones
   npm test             # game engine tests (Jest)
   ```

To play solo, start a game and tap **Start (just me)**.
To look at every damage level, the bomb animation, the table view and a results screen with fake data (no Firebase needed), open `/dev/fx` (on web: `http://localhost:8081/dev/fx`).

## Project layout

```
app/                    expo-router routes (thin: re-export screens)
src/game/               pure game engine: rules, ranking, awards, damage, detector, FX geometry (+ tests)
src/api/                Firestore only lives here: sessions (transactions), users, parsers (+ tests)
src/store/              Zustand stores: auth, session (subscriptions + write queue), history, settings
src/hooks/              usePickupDetector, useGameFeedback, routing gate
src/components/avatar/  AvatarFace, DamageOverlay (cracks/band-aid/soot/flames), Explosion (bomb + shards), DamagedAvatar
src/components/game/    TableRing, PlayerStat, EventFeed, ModeCard, StakeBanner
src/screens/            onboarding, home, create, join, session (Lobby/Live/Results), profile, dev/fx
assets/sounds/          generated by scripts/generate-sounds.py
firestore.rules         every client write path is covered
```

The architecture rules follow CoMission (see `.cursorrules`): Component → Store → API → Firestore; flat models; no `Alert.alert`; fail fast.

## Data model (Firestore)

- `users/{uid}`: `name`, `photoURL` (JPEG data URI or null), `createdAt`
- `sessions/{id}`: code, host, mode, settings, stake, `status` (`lobby` | `live` | `finished`), `playerIds`, `aliveIds`, timing, and the final `rankedIds` / `winnerId` / `loserId`
- `sessions/{id}/players/{uid}`: pickups, holding state, time off the table, longest hold, out/outAt
- `sessions/{id}/events/{auto}`: the running commentary (joined, placed, pickup, putdown, eliminated)

Game rules run on the clients inside Firestore transactions. There are no Cloud Functions. Any phone at the table can end a game whose timer has run out, and any phone can knock out a Time Bank player whose budget is empty.
